# Release 0.1.1

This release reduces operator dispatch overhead, adds guarded CUDA indexing
specializations, and includes the experimental Kernel Hub adapter in the source
repository. The PyPI package continues to support CPU, CUDA and Apple Silicon MPS.

## CUDA metadata validation

`ms_deform_attn` now accepts the keyword-only argument
`check_cuda_metadata=False`. CUDA still validates tensor shapes, dtypes, devices
and layout, but trusts spatial-shape and level-start tensor contents by default
to avoid the validation kernel and synchronization on each call.

Each feature level must have positive height and width, a nonnegative start,
and `start + height * width <= value.shape[1]`. Invalid unchecked contents can
produce incorrect results or illegal memory accesses. To retain `0.1.0`'s CUDA
content checks, set the flag explicitly:

```python
output = ms_deform_attn(
    value, shapes, starts, locations, weights,
    check_cuda_metadata=True,
)
```

The flag is preserved for backward and captured by `torch.compile`, export and
CUDA Graphs. CPU and MPS continue to validate metadata contents on every call.
See the [API contract](../api.md#cuda-constraints-and-errors).

## Implementation and validation tooling

- Register the operators and first-order autograd in C++ to reduce Python
  dispatch overhead while preserving FakeTensor and compilation support.
- Use guarded 32-bit CUDA indexing and specialized index decomposition where
  the indexing bounds permit it, retaining the wider indexing path otherwise.
- Add CUDA Graph and indexing regression coverage. Low-precision inputs still
  compute in float32; native low-precision arithmetic and higher-order gradients
  remain unsupported.
- Add an experimental CUDA-only Kernel Hub export and RT-DETR comparison
  harness in the repository. This is not a published or adopted HF kernel;
  PyPI installation does not install a Kernel Hub distribution.
- Extend Nix PR build coverage and support explicit build selection plus
  archived distribution/evidence retrieval.
- Update uv to 0.13.5, pip to >=26.2.2, and the PyPI publishing action to 1.14.3
  for the October 2026 eMudhra certificate incident. Verify the uv bootstrap
  archive against its committed SHA-256 and use an isolated, checked certifi
  trust store for Runpod API requests. See the
  [TLS tooling baseline](../development.md#tls-tooling-baseline).

Python >=3.10 and PyTorch >=2.4,<3 requirements are unchanged. Distribution is
still an sdist compiled against the user's installed PyTorch. Rebuild the
extension when upgrading this package or changing the PyTorch environment.
Release-specific validation and its exact source SHA are recorded in the
[GitHub release](https://github.com/S-aiueo32/torch-ms-deform-attn/releases/tag/v0.1.1).
